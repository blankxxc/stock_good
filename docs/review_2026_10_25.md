三个 subagent 分别检查前端、AI 接口与数据逻辑；部分子任务受用量限制中断，主代理接手已保存的复现用例、修复与验证。未读取真实 API Key，未发起付费模型调用，也未重新拉行情或训练模型。

## 已修复

| 问题 | 触发方式与影响 | 修复 |
| --- | --- | --- |
| 百分比筛选单位不一致 | 显示 15% 的收益率，输入 10 原先按原值 10 比较，误筛成 1000% | 百分比列按显示的百分数输入，并明确输入单位 |
| 隐藏因子后留下筛选状态 | 移除因子列后过滤失效，但计数和助手摘要仍包含原条件 | 隐藏列时清理对应条件；计数和摘要只包含当前可见条件 |
| 条件表一次渲染全部股票 | 300 行乘多列，筛选和切换列增加 DOM 工作 | 默认每页 50 行，可选 25/50/100；先全量筛选再分页，筛选变动回到第一页 |
| 配置 Key 后回错页面 | 从 API 预测进入个人设置，返回仅保留 /scores，丢失模型与股票 | 保留经过校验的公开查询参数，手动选股也更新返回位置 |
| 侧边助手混入旧股票分析 | 预测页切换股票时 pathname 与模型不变，旧对话和请求仍存续 | 根据当前股票重置对话、取消请求，并忽略迟到输出 |
| 取消 AI 请求未释放资源 | 聊天正文开始前断开可泄漏并发名额；方案/预测在客户端离开后仍等待模型 | 响应生命周期负责关闭流及释放名额，非流式请求监测断开并取消上游等待 |
| 数据更新时元数据可能混用版本 | 旧元数据读完后才打上新版本，后续一致性检查无法发现 | 元数据读取前后检查版本，变化则拒绝本次读取 |
| 晚到因子进入历史输入 | 有值但可用时间晚于预测时点，或者时间缺失 | 保持 null；同时支持 ISO 时间文本和有时区的时间戳列 |

## 检查证据

- 前端运行测试 43 项、后端相关回归 158 项通过，TypeScript 检查和生产构建通过。
- 真实本地数据的两只股票、8 个因子、30 日价格、252 个历史窗口通过模拟供应商接口联调；数据截止日仍为 2026-10-19。
- 原网站浏览器 gzip 已启用：条件选股 JSON 789203 字节压至 161474 字节；因此未重复添加压缩中间件。
- 检查前暖接口响应约 13–47 毫秒，条件页约 125–203 毫秒，属于本机 HTTP 测量，不代表浏览器完整交互耗时。
- 分页将默认渲染的数据行从 300 减至 50，减少约 83%；未声称浏览器速度同比提高 83%。
- 本次后端重启后实测：条件选股第一次读取 27563 毫秒，紧接着的缓存请求 115 毫秒。冷启动重算历史指标仍是明确瓶颈；这次没有将其隐藏为已解决的问题。
